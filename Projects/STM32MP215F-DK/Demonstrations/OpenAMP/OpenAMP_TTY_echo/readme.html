OpenAMP_TTY_echo Demonstration (CM33 NonSecure)

Application Description

The OpenAMP_TTY_echo demonstration shows how to use the OpenAMP middleware and Virtual UART to create an Inter-Processor Communication (IPC) channel that appears as a TTY device (/dev/ttyRPMSGx) inside Linux running on the CA35.

  • CM33 acts as the REMOTE processor. It runs as a bare-metal firmware, started and stopped by Linux via the RemoteProc framework.
  • CA35 acts as the HOST (OpenAMP RPROC master). Linux controls the CM33 lifecycle and exchanges messages through the RPMsg/VirtIO transport over IPCC1.
  • The CM33 creates two Virtual UART channels (VirtUART0 → /dev/ttyRPMSG0, VirtUART1 → /dev/ttyRPMSG1) and echoes back every message it receives.
  • LED3 (orange) toggles on each successfully received message.

How It Works

  1. Linux loads the signed CM33 firmware via RemoteProc and starts the remote processor.
  2. The CM33 initialises IPCC1, sets up the resource table, and registers VirtUART0 and VirtUART1 RPMsg endpoints.
  3. When Linux writes to /dev/ttyRPMSG0 or /dev/ttyRPMSG1, the CM33 receives the message, toggles LED3, and sends the same data back.
  4. Linux reads the echoed data from the same device node.

Expected Success Behavior

  • LED3 (orange) toggles on each message received from Linux.
  • Data written to /dev/ttyRPMSG0 and /dev/ttyRPMSG1 is echoed back and visible in the Linux console.

Error Behaviors

  • LED3 (orange) does not blink: CM33 firmware did not start or VirtUART initialisation failed. Check that the signed binary is correctly placed and RemoteProc state is running.

Hardware and Software Environment

  • This demonstration runs on STM32MP21xxxx devices.
  • Tested with STMicroelectronics STM32MP215F-DK board.
  • Linux must be running on CA35 with RemoteProc and RPMsg support enabled in the kernel.
  • Connect an ST-Link cable to the PC USB port to observe CM33 trace output.

To Build with CMake (Command Line)

Navigate to the project root directory (Firmware/Projects/STM32MP215F-DK/Demonstrations/OpenAMP/OpenAMP_TTY_echo):

  1. Configure: bash cmake -G"Unix Makefiles" -B build

    On Windows with STM32CubeIDE, add the toolchain and make paths to PATH first. Example (STM32CubeIDE 1.19.0): bash export PATH="/c/ST/STM32CubeIDE_1.19.0.25A9/STM32CubeIDE/plugins/\ com.st.stm32cube.ide.mcu.externaltools.gnu-tools-for-stm32.13.3.rel1.win32_1.0.0.202411081344/tools/bin:\ /c/ST/STM32CubeIDE_1.19.0.25A9/STM32CubeIDE/plugins/\ com.st.stm32cube.ide.mcu.externaltools.make.win32_2.2.0.202409170845/tools/bin:$PATH"

  2. Build: bash cmake --build build or equivalently: bash make -C build all

How to Deploy and Run

  1. Copy OpenAMP_TTY_echo_CM33_NonSecure_sign.bin to the Linux filesystem on the target board.

  2. Place it in the RemoteProc firmware search path, for example: bash cp OpenAMP_TTY_echo_CM33_NonSecure_sign.bin /lib/firmware/

  3. Load and start the CM33 firmware: bash echo OpenAMP_TTY_echo_CM33_NonSecure_sign.bin > /sys/class/remoteproc/remoteproc0/firmware echo start > /sys/class/remoteproc/remoteproc0/state

  4. Configure the VirtUART channels and send test messages: bash stty -onlcr -echo -F /dev/ttyRPMSG0 cat /dev/ttyRPMSG0 & stty -onlcr -echo -F /dev/ttyRPMSG1 cat /dev/ttyRPMSG1 & echo "Hello Virtual UART0" > /dev/ttyRPMSG0 echo "Hello Virtual UART1" > /dev/ttyRPMSG1

  5. Expected output in the Linux console: Hello Virtual UART0 Hello Virtual UART1

  6. To stop the CM33 firmware: bash echo stop > /sys/class/remoteproc/remoteproc0/state
