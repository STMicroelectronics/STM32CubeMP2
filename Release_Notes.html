Release Notes for STM32CubeMP2 Firmware Package

Copyright © 2024 STMicroelectronics

Purpose

STMCube is an STMicroelectronics original initiative to ease developers life by reducing development efforts, time and cost.

STM32Cube covers STM32 portfolio.

STM32Cube Version 1.x includes:

  • The STM32CubeMX, a graphical software configuration tool that allows to generate C initialization code using graphical wizards.

  • A comprehensive embedded software platform, delivered per series

    • The STM32Cube HAL, an STM32 abstraction layer embedded software, ensuring maximized portability across STM32 portfolio.HAL APIs are available for all peripherals.

    • Low-layer APIs (LL) offering a fast light-weight expert-oriented layer which is closer to the hardware than the HAL. LL APIs are available only for a set of peripherals.

    • A consistent set of middleware components such as FreeRTOS, OpenAMP.

    • All embedded software utilities, delivered with a full set of examples.

The STM32Cube firmware solution offers a straightforward API with a modular architecture, making it simple to fine tune custom applications and scalable to fit most requirements.

The drivers provided within this package support the STM32MP251/253/257 lines.

Main Changes

Contents

  • This is the v1.4.0 release of STM32CubeMP2 cube firmware.

v1.4.0 release

  • Deliver SBOM in CycloneDX v1.5 format
  • OpenAMP_TTY_echo project is added as a demonstration project for all the supported boards.
    • Cmake compilation is supported for all demonstration project.
  • Rename _HAL_RCC_LPDMA_CLK_ENABLE to _HAL_RCC_LPDMA1_CLK_ENABLE to align with CubeMX convention.
  • Add deinit of DCache, ICache during Copro shutdown of the example projects to prevent any issue in subsequent runs.
  • Initialize the stack-limit register (MSPLIM) in startup files to help prevent secure-stack overwrite by non-secure code if a stack overflow occurs.
  • Fix RCC HSI calibration save/restore so  HAL_RCC_GetOscConfig()  returns the correct trimming value and prevents frequency drift after reconfiguration.
  • Fix OpenAMP Middleware configuration across all projects to define  NO_ATOMIC_64_SUPPORT , which prevents linker errors on 32-bit systems.
  • ADC Sample clock cycle names updated to match terminology used in the Refernce Manual.
  • StarterApp improvements:
    • Unify A35 warm-reboot and crash/resume recovery through RemoteProcTask, stopping stale M33 vring processing and restarting A35 after CPU_OFFLINE to prevent RPMsg assertions.
  • M33TD_NSAppCore:
    • Updated to use new OpenAMP middleware version.
  • Documentation updated for all StarterApp like applications.
  • External-DT is no longer part of the Cube Firmware release.
  • Optee scripts updated to newer version.
  • mbedTLS is now supported. 2 New Applications are added to demonstrate its usage.
  • MISRA warnings are fixed for a number of drivers.
  • Spelling corrections have been done on a number of drivers and applications.
  • Miscellaneous bug fixes.

  • Support added for M33TDCID Boot configuration (Cortex-M33 as Trusted Domain Master) of the platform.

  • LwIP applications added for all boards.
  • All examples are updated to use ICache and DCache.
  • MP25/MP23 examples are updated to use a common linker file.
  • HAL Driver updates for: ADC, DCMIPP, DMA, ETH, EXTI, GPIO, RIF, USB
  • CMSIS has been updated.
  • Updates to ResourceManager.
  • Updates to BSP for STM32MP257F-EV1, STM32MP257F-DK, STM32MP235F-DK, STM32MP215F-DK

Main Changes

  • This is the Alpha1 release of the STM32CubeMP2 Firmware Package.
  • This release adds support for Baremetal Program on the STM32CubeMP2 Firmware Package.
  • Applications based on OpenBootLoader are included which enables users to flash boot images on the permanent storages (sdcard, eMMC and sNOR).
  • User can now run Cube Firmware (Secure mode) on Cortex-A35 (in AARCH32 mode).
  • 4 New Projects added for Baremetal Mode (2 Templates and 2 Demonstrations)
  • Booting via an external storage (sdcard, eMMC and sNOR) is supported allowing customers to deploy applications in production.

v1.4.0RC4 (Alpha1 Baremetal release)

  • Following STM32 HAL drivers have been validated to run on Cortex-A35:
    • System (Cortex-A, DDR, DMA, GPIO, EXTI, RCC, PWR, RIF)
    • Analog (ADC)
    • Connectivity (UART, USART, I2C, SPI)
    • Control and Debug (TIM, LPTIM)
    • High Speed Link (ETH, USB Host, USBOTG )
    • Storage (OSPI, SDMMC, FMC-NAND)
    • Security (CRC, RTC (without TAMP))
    • Visual (DCMIPP+CSIHost, LTDC, DSI)
  • Support Boot of MP2 platform from External storage for BareMetal execution.
    • Boot from 3 External storage medias (SDCard, eMMC and sNOR)
  • following components are added which help prepare the system to boot correctly:
    • FSBL-A (Jumper) : Sets up Cortex-A35 and jumps to BareMetal Cube Firmware application.
    • DeviceTree: A data structure that defines the hardware configuration including security of the Baremetal system.
      • Used during compilation of TF-M and Mcuboot (FSBL-M) to setup system firewall.
    • External Memory Flashing Applications(Based on OpenBootLoader)
      • 6 New Application projects added to enable writing images on SDcard, eMMC and sNOR.
  • Updated utilities to be usable from Cube Firmware CA35 (BareMetal context)
    • Scmiagent: Library to help asynchronous communication with SCMI server running on TFM (Cortex-M33)
    • ResourcesManager: Helps acquire IP resource instances which can be used from any given master.
  • Templates and Demonstration projects
    • 4 New projects added (2 Templates and 2 Demonstrations)
    • Demo application showcases how Cube Firmware running on Cortext-A35 can configure and communicate using SCMI protocol.

  • Support (Beta) for using Cortex-M33 as Trusted Domain Master a.k.a M33TDCID configuration of STM32MP2x MPU Platforms.

v1.2.0 release

  • Delivered SBOM in CycloneDX v1.5 format.

  • Added support for MP21 (new SOC MP21 Cube Firmware Mass Market)
    • Added CMSIS for all CPNs of this derivative.
    • Added BSP for a new Board STM32MP215F-DK.
    • Added new examples, Applications and Demonstration projects for MP21.
    • ResourceManager updated to handle requests for MP21 resources.
    • Added STPMIC2L: new BSP pmic lighter component support.
  • MP2x General updates
    • MP25: Software Workaround added to CM0Plus demo application to prevent crash when D1/D2 domains enter/exit low power states.
    • Bug fixes to scmiagent middleware
    • USBPD applications updated to enable use of SCMI to control power regulator.
    • Free RTOS Middleware update to cater CVE fixes.
    • Upgraded to TFM version v2.1.0
    • General bug fixes and known issues.
  • Support for using Cortex-M33 as Trusted Domain Master of system.
    • Here CM33 acts as Master of System and defines/controls security of the system.
    • A CM33 Non-Secure Starter Application is provided as part of firmware package.
    • This application is used in conjuction with Trusted Firmware - M.
    • Please refer to ST Wiki to know details about this usage.

Main Changes

  • This is a Maintenance release of STM32CubeMP2 Firmware Package

v1.1.0 release

  • Added support for a new derivative of MP2x: MP23
    • Added CMSIS for all CPNs of this derivative.
    • Added BSP for a new Board STM32MP235F-DK (This board is not available, but a BSP is available which has been tested on STM32MP257F-DK board)
    • Added new examples, Applications and Demonstration projects for MP23.
    • ResourceManager updated to handle requests for MP23 resources.
  • MP25: Support added for Cortex-M0
    • CMSIS for all CPNs available.
    • OpenOCD scripts updated to support CM0+ project compilation.
    • Demonstration project running in production mode showing usage of LPUART
      • Cortex-M0 firmware is running in production mode.
      • Added script fw_cortex_m0.sh to load, start, stop the firmware.
      • This project can be compiled using Cmake or STM32CubeIDE.
      • Uses Open config of OSTL.
  • CMSIS updated to v5.9.0
  • MP25: Low Power modes demonstration.
    • Demo Cube Firmware project that is loaded and executed from the SRAM in production mode.
  • MP2x: Support added to encrypt the Cube Firmware and decrypt when loaded on M33.
  • MP25: Support to switch ON/OFF UCPD power supply VDD3UCPD.
    • Achieved through controlling PMIC regulator by virtue of SCMI inter-processor communication with SCMI server running on OPTEE (Secure OS running on CA35).
  • MP2x: Updated Resource Manager
    • Support for multiple GPIO pins request/release.
    • Support to request RTC features as resources.
    • Bug Fixes, refactoring of codebase to allow addition of MP2x derivatives.
  • MP25: Support added for 16x16 package.
  • MP2x: Miscellaneous bug fixes in DMA, GPIO, RCC
  • Misra, MCUAstyle fixes.
  • General Code cleanup

Notes

  • All the examples/projects delivered in this release are meant to be run in Production mode.
  • Production boot mode
    • Firmware is loaded in coprocessor by the master processor (Cortex A35 - Flash Memory boot mode)
    • You would need to install the OSTL images on SDCard (please refer to the ST Wiki)
    • OSTL images come with different configurations and images from each configuration can be flashed on a storage media like SDCard.
      • Path of configuration files (.tsv files): ‘images/stm32mp2/flashlayout_st-image-weston/optee/’
    • The configuration suitable to run the above examples is the one with ca35tdcid-ostl-m33-examples embedded in the name.
  • ResourceManager is used in all examples to request/acquire hardware resources needed for the functionality demonstrated.
  • To build examples/apps using STM32CubeIDE:
    • Select config CA35TDCID_m33_ns_sign :
    • Building using selected config generates a signed firmware binary.
  • Copy signed firmware binaries to the root filesystem on the board (Assuming you have connected to board on USB Port).
    $ ssh root@192.168.7.1  'mkdir -p /home/root/<EXAMPLE_NAME>/lib/firmware'
    $ scp <SIGNED_FIRMWARE> root@192.168.7.1:/home/root/<EXAMPLE_NAME>/lib/firmware/
    $ scp fw_cortex_m33.sh root@192.168.7.1:/home/root/<EXAMPLE_NAME>/
  • To run examples/apps on target:
    • On the target shell run: 'cd /home/root/<EXAMPLE_NAME>/ ; ./fw_cortex_m33.sh start'

Demonstrations

  • USBPD_DRP_UCSI: This demonstration project would be functional when OSTL images are flashed with configuration files (.TSV file) (without ca35tdcid-ostl-m33-examples embedded in the name.).

LTDC 3rd Layer Example

  • This example demonstrates how we can display some content on Layer 3 of LTDC from CM33 while Layer 1 and 2 are being used by CA35.
  • How to Run:
    • Compile the example and copy it to a folder on the root filesystem on the board as described above.
    • Use the configuration ca35tdcid-ostl-m33-examples while flashing the OSTL images on SDcard.
    • Connect the panel to the EV1 board.
    • When you boot the system, the default animation and display controlled by CA35(running Linux) will show up rendering on Layer 1 and Layer 2.
    • Now start the LTDC example, It will display the contents on Layer3 while the content from CA35 will still be visible in the back layers.
